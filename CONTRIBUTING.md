# Contributing to ALTERIA

Fork the repository, create a focused branch and open a pull request. Start with [the development guide](docs/DEVELOPMENT.md). Keep source, documentation and hardware revision consistent.

Describe the problem, the change, board/MCU and firmware version, build command and memory use, tests run, and what still needs a physical test. Include measured conditions for electrical claims. Preserve licenses and attribution. Avoid committing generated build directories, local settings, credentials or unrelated files.

For hardware changes provide editable CAD, PDF, matching BOM, Gerbers and an explicit connector/pinout diff. For firmware changes document control mappings, I/O direction, timing and persistence changes. Report a bug through GitHub Issues with reproduction steps and the exact revision; distinguish observations from assumptions.
